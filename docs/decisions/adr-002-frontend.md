# ADR-002: Frontend Framework

**Status:** Accepted

**Date:** 2026-10-13

---

## Context

No frontend code existed. Feature `001-gl-account-maintenance` has six UX screens
(`specs/001-gl-account-maintenance/ux/`) whose components were all recorded as design-system gaps
until a framework was chosen. The API is a stub-data REST service (ADR-001, OpenAPI authoritative) with
no authentication (spec Q-001).

---

## Options considered

| Option | Notes |
|---|---|
| ASP.NET Core Razor Pages / MVC (server-rendered) | Lowest JS complexity; Playwright for browser tests |
| Blazor WebAssembly / Server | .NET-native |
| React + Vite | Most flexible; requires TypeScript toolchain |
| Next.js | Only if SSR/SSG is needed |
| Vue 3 | Alternative to React |
| **Angular** | Chosen by the product owner |
| No frontend (API-only) | Not wanted for this feature |

---

## Decision

**[X] Option selected:** Angular (standalone components, TypeScript strict, Angular Router with lazy-loaded feature routes, Reactive Forms).

**Component library:** Angular Material (official, accessible; provides the table, paginator, sort header, dialog, form field, select, datepicker, button and snackbar components). Components Material does not provide (for example `DescriptionList`, `StatusBadge`, `BlockerList`, `EmptyState`, `ErrorBanner`) stay recorded as design-system gaps in `ux/component-map.yaml` and are built as thin wrappers composed from Material and semantic HTML, not as a second library.

**Build tool:** Angular CLI (default application builder). Package manager: npm.

**Testing:** the unit-test runner generated by the Angular CLI for component and service tests; Playwright for browser journeys; `@axe-core/playwright` for accessibility checks.

**Location:** `src/GlAccounts.Web/`.

**API access:** the browser calls relative `/api/...` URLs. In development the Angular dev server proxies `/api` to `http://localhost:5000` (the API's `launchSettings.json` URL), so no CORS change to the API is required. Production hosting of the built UI is not decided here.

**State:** component and service state with Angular signals; no NgRx or second store library. Server state (account, ETag) is kept apart from UI state (form values, dialog open).

**Out of scope:** authentication and authorization (Q-001); the `forbidden` state stays reserved and unreachable.

---

## Consequences

- The UI is only as verified as the stub data behind it: "not verified (stub data)" applies to durability and concurrency.
- Node.js and npm are required to build and test the UI, in addition to the .NET SDK.
- Design-system gaps remain for the custom wrappers listed above and need human review (`frontend.md`).
- `plan.md` and `spec.md` still say the frontend is undecided; this ADR supersedes those statements.
